# День показа Synaps

Все команды — на `ssh root@31.77.251.162`, из `/opt/synaps`; Python 3, Docker Compose уже установлены.

1. **Накануне.** Создать аккаунт Clore, пополнить баланс, записать `CLORE_API_KEY` и
   `CLORE_CURRENCY=USD-Blockchain` в `deploy/.env` (не публиковать файл). Выполнить:
   ```bash
   python3 deploy/clore.py find
   python3 deploy/clore.py up --primary <5090-id> --backup <3090-id> --hours 6 --dry-run
   ```
   Выбирать разные серверы и владельцев: primary RTX 5090 32 ГБ, backup RTX 3090 24 ГБ.
   Цены **за день**, не за час: бюджет на N часов = `(5090 $/день + 3090 $/день) × N / 24`.
   Пример рынка 15.11: $7.99 + $3.00 → $2.75 за 6 часов; пополнить хотя бы $5–10
   с запасом на комиссии/изменение цен и репетицию. ID и цены перепроверять через `find`.
   Сделать первую реальную репетицию заранее: запуск Clore и память GPU без аренды не проверены.
   Сохранить завершённый прогон в пульте, записать видео/скриншоты на ноутбук.

2. **За 2 часа.** Повторить `find` (GPU мог занять другой арендатор), затем:
   ```bash
   python3 deploy/clore.py up --primary <5090-id> --backup <3090-id> --hours 6
   python3 deploy/clore.py status
   ```
   Скачивается ~17 ГБ на каждый GPU; ожидание до 40 минут, затем обычный и JSON-schema прогрев.
   `up` сохраняет id заказов сразу; при ошибке они НЕ отменяются: `status`, затем `down`.
   При неопределённом ответе create_order сначала проверить My Orders в Clore UI, не повторять аренду вслепую.
   `deploy/.env.bak` и `backend/.env.bak` создаются один раз; это секретные файлы, не коммитить.
   В пульте http://31.77.251.162/console/ выбрать серверную модель (не старый облачный профиль),
   запустить один демо-эпик полностью, проверить агентов, результат, кнопку «В Jira» и созданные задачи.
   Проверить `/api/health`: `qwen3.8-27b`, concurrency 4, json_schema; заранее проверить срок Jira-токена.

3. **На выступлении.** Показать запуск эпика, живых агентов, результат и кнопку «В Jira». «Лаборатория» скрыта из меню (открывается по адресу `#/lab`).
   На ноутбуке открыть статистику:
   ```bash
   ssh -L 8404:127.0.0.1:8404 root@31.77.251.162
   ```
   http://localhost:8404 → primary/backup UP. В отдельном SSH-сеансе:
   ```bash
   cd /opt/synaps
   python3 deploy/clore.py failover
   python3 deploy/clore.py restore
   ```
   `failover` ставит primary в MAINT, отправляет запрос и подтверждает рост `backup stot`.
   Дождаться окончания текущего шага перед переключением: уже открытый поток не мигрирует на backup,
   демонстрация доказывает обслуживание новых запросов. После рестарта HAProxy maintenance сбрасывается.

4. **Запасной план.** Если GPU или интернет пропал — открыть сохранённый завершённый прогон в пульте,
   пройти его историю/события и результат вместо новой генерации. При недоступности самого стенда — локальное видео.
   Если JSON-schema прогрев не прошёл, не продолжать вслепую: установить `LLM_JSON_MODE=json_object`
   в `backend/.env`, пересоздать backend и проверить полный эпик. Повторный `up` снова выставляет json_schema.
   Аренду через UI можно подключить без Clore API:
   `python3 deploy/clore.py up --attach host:port,host:port` (скрытый режим; тот же `LLM_API_KEY`
   заранее выставить в deploy/.env и обеих моделях). Здесь `down` только отсоединяет — ручные заказы отменять в UI.

5. **После.** `python3 deploy/clore.py down` (или `down --yes`); проверить My Orders в Clore UI.
   Заказы из state отменяются, адреса HAProxy → `127.0.0.1:9`; backend остаётся с настройками Qwen.
   GPU-часы/расходы в `status` — оценка, без комиссий; окончательный счёт смотреть в Clore.

## Что именно запускается

Закреплённый digest `ghcr.io/ggml-org/llama.cpp:server-cuda` указан в `deploy/clore.py`.
Проверено Docker inspect и запуском `--help`: бинарник `/app/llama-server`, CUDA **12.8.1**;
`find` требует CUDA host ≥ 12.8 (Clore публикует major.minor).
Параметры: `-hf unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_M --no-mmproj -ngl 999 -c 98304 -np 4
--cache-type-k q8_0 --cache-type-v q8_0 -fa on --jinja --alias qwen3.8-27b --api-key …`,
слушает `0.0.0.0:8080`, включены `/slots` и `/metrics`. `-hf repo:quant` подтверждён
[README llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md):
mmproj скачивается автоматически, поэтому явно отключён. Файл `Qwen3.8-27B-UD-Q4_K_M.gguf`
есть в [репозитории модели](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF).
Общий контекст 98304 / 4 = 24576 токенов на слот; расчёт памяти для 24 ГБ требует проверки реальной загрузкой.

Проверено на живой аренде 15.11 (RTX 3090, сервер 85425):
- без `autossh_entrypoint` Clore запускает ENTRYPOINT образа (`/app/llama-server`) **без аргументов**: получается
  llama-server в режиме router — без модели, без ключа, открытый наружу; `command` при этом не применяется;
- с `autossh_entrypoint: true` Clore поднимает SSH и выполняет `command` как стартовый скрипт `/root/onstart.sh`.
  Поэтому сервер запускается в фоне: `cd /app && nohup ./llama-server … > /root/llama.log 2>&1 &`;
- `create_order` отвечает только `{"code": 0}` без номера — скрипт находит новый заказ в `my_orders` по `si`
  (id сервера); у заказа нет поля `status`, готовность — `online: true` и порт в `tcp_ports`;
- адрес: `pub_cluster[0]` + внешний порт из `tcp_ports` (`["22:1345", "8080:1346"]` → `n1.de.clorecloud.net:1346`),
  SSH: `ssh -p <порт 22> root@<pub_cluster>` по ключу; лог модели — `/root/llama.log`;
- от заказа до готовой модели — около 3 минут (образ + 17 ГБ модели); у заказа есть разовая комиссия $0.10.
Рассуждения модели выключены на стороне llama-server (`--reasoning-budget 0`), чтобы это действовало и для
провайдера из пульта, который `LLM_EXTRA_BODY` не передаёт.
Raw JSON первого my_orders сохраняется с редактированием секретов в `deploy/clore-state.json` (0600),
для диагностики TCP mapping; неизвестный формат портов потребует сверки в UI.
Ключ и HTTP-запросы идут к GPU открытым TCP: использовать только демо-данные, ограничить доступ
IP стенда на стороне провайдера при возможности. SSH-пароль генерируется, не выводится, хранится только в state (0600). При неопределённом
create_order маркер `creation_pending` блокирует повторный `up`: сначала сверить My Orders,
отменить возможный лишний заказ и только после этого удалить маркер вручную.
