# SYNAPS — фронтенд

React 19 + TypeScript + Vite 8 + Tailwind CSS 4. Линтер — oxlint.
Нужны npm и Node.js, соответствующий требованию Vite: `^20.19.0 || >=22.12.0`.

## Быстрый старт

Для просмотра лендинга и витрины агентов бэкенд не нужен. Из корня репозитория:

```bash
cd frontend
npm install
npm run dev
```

| Адрес | Назначение |
| --- | --- |
| `http://localhost:5173/` | Лендинг с демонстрационной сценой: NAPS и 9 ролей агентов |
| `http://localhost:5173/agents/` | Витрина 9 ролей в состояниях ожидания, работы и успеха |
| `http://localhost:5173/console/` | Рабочий пульт; для данных и запуска декомпозиции нужен бэкенд |

Лендинг и витрина не обращаются к API. Отладка демонстрационной анимации:
`http://localhost:5173/?t=8.5` фиксирует сцену на отметке 8.5 секунды.

Для работы пульта запустите бэкенд **в отдельном терминале**, также из корня репозитория:

```bash
cd backend
uv sync
uv run uvicorn app.main:app --reload --port 8000 --timeout-graceful-shutdown 2
```

Перед первым запуском настройте модель по [инструкции бэкенда](../backend/README.md).
Без работающей LLM можно открыть интерфейс и сохранённые прогоны, но новая декомпозиция не выполнится.

Vite dev-сервер проксирует `/api` на `http://localhost:8000`. Другой адрес задаётся при запуске из `frontend/`:

```bash
API_URL=http://localhost:9000 npm run dev
```

Это настройка прокси сервера разработки, не адрес LLM. Ключи моделей хранит бэкенд.

## Команды

Выполняются из `frontend/`:

```bash
npm run dev      # сервер разработки с HMR
npm run build    # проверка типов (tsc -b) и сборка трёх страниц в dist/
npm run lint     # oxlint
npm run preview  # локальный просмотр готовой сборки
```

`preview` не заменяет бэкенд и не использует dev-прокси `/api`. Для полной работы собранного пульта
нужен обратный прокси, как в [Docker-развёртывании](../backend/README.md#запуск-в-docker).

## Маршруты пульта

Маршруты добавляются после `/console/`, например `/console/#/runs`.

| Хеш | Экран |
| --- | --- |
| `#/` | Новый эпик: своя задача с документами или готовый демо-сценарий |
| `#/runs` | Журнал запусков |
| `#/models` | Провайдеры OpenAI-совместимых API и их модели |
| `#/prompts` | Редактирование и сброс системных промптов |
| `#/bench` | Сводка и отчёты бенчмарка проверяющих агентов |
| `#/run/<id>` | Прогон в режиме «Агенты»: граф работы и инспектор агента |
| `#/run/<id>/pult` | Тот же прогон в режиме «Пульт»: карта, таблица, ОТК и пробелы |
| `#/lab` | Лаборатория сравнения с декомпозицией аналитика; маршрут сохранён, но пункта в меню нет |

Провайдер, модель и начальное число параллельных запросов выбираются в оболочке консоли;
выбор сохраняется в `localStorage`. Провайдеры, промпты и результаты хранятся на бэкенде.

## Работа с прогоном

- В режиме «Агенты» видны входы, поток рассуждений и ответ модели, результаты и хронология вызовов.
  Генератор задач и рецензент создаются на каждую историю. Архитектор показывается для прогонов с ним;
  старые записи и прогоны без Архитектора отображаются без него.
- В режиме «Пульт» доступны трассировочная карта «источник → требование → история → задача»,
  редактирование результата, проверки покрытия и пробелы. На широком экране карта переключается
  между видом по историям и колонками; стрелки вверх/вниз выбирают соседнюю историю.
- При уточняющих вопросах появляется форма ответов. Идущий прогон можно поставить на паузу
  и продолжить; число параллельных запросов меняется и во время работы.
- Записи завершённых и неудачных прогонов можно проиграть с ускорением 4×, 10× или 25×.
- Готовый результат скачивается в DOCX, XLSX и JSON. ZIP содержит материалы и историю прогона;
  в интерфейсе ссылка доступна, когда статус отличается от `running`.
- Кнопка «В Jira» появляется при настроенной интеграции и доступна для готового результата.

Холст графа: перетаскивание перемещает, колесо мыши и щипок масштабируют, двойной клик по фону
вписывает граф. На сфокусированном холсте работают `+`, `-`, `0` и стрелки.
На сенсорном экране один палец перемещает холст, два — масштабируют и перемещают.

### На телефоне

Вместо постоянной боковой панели используется меню под кнопкой в верхней строке.
В режиме «Агенты» инспектор раскрывается снизу при выборе узла и сворачивается ручкой шторки;
в пульте сведения о выбранном узле также открываются нижней панелью.
Пауза, параллельность, воспроизведение и выгрузки собраны под кнопкой «⋯» в шапке прогона.

Дизайн и исходный контракт событий: [спецификация консоли](../docs/superpowers/specs/2026-11-14-console-design.md).
Текущие маршруты и обработчики событий — в `src/shared/lib/useHashRoute.ts` и
`src/features/run-stream/model/useRunStream.ts`.

## Структура

Код организован по слоям `app → pages → widgets → features → entities → shared`.
Публичные экспорты срезов находятся в `index.ts`, алиас `@/` указывает на `src/`.

```text
src/
  app/                 App, ConsoleApp, AgentsApp; стили index.css и console.css
  pages/
    home/              компоновка лендинга
    console/           выбор экрана по хеш-маршруту
    agents/            витрина 9 ролей в трёх состояниях
  widgets/
    site-header/       шапка лендинга
    hero/              заголовок и вводная часть
    agent-stage/       демонстрационная SVG-сцена NAPS и 9 ролей
    site-footer/       подвал лендинга
    console-shell/     боковая панель / мобильное меню, выбор модели, статус API
    launch-panel/      форма эпика, документы, серверные демо и локальные шаблоны
    runs-list/         журнал запусков
    models-panel/      управление провайдерами моделей
    prompts-panel/     редактор системных промптов
    bench-panel/       сводка и отчёты бенчмарка, Markdown-рендерер
    lab-panel/         сравнение с декомпозицией аналитика; скрыт из меню
    run-workspace/     компоновка графа агентов или пульта
    agent-flow/        граф экземпляров агентов, шапка прогона и инспектор агента
    run-progress/      этапы прогона и подробности проверок
    trace-map/         трассировочная карта по историям или колонками
    inspector/         источники, требования и задачи выбранного узла карты
    telemetry/         поток модели и журнал событий
    questions-panel/   ответы на уточняющие вопросы
    results-table/     таблица и редактирование результата
    qc-report/         отчёт проверок и покрытия
    gaps-board/        пробелы и противоречия
  features/
    team-run/          сценарий и тайминги демонстрации лендинга
    export-result/     копирование и Markdown-выгрузка демонстрационного результата
    run-stream/        SSE-события → состояние прогона, воспроизведение записи
    launch-run/        API запуска своего эпика и демо
    answer-questions/  API ответов аналитику
    edit-result/       API правки результата
    run-control/       API паузы, продолжения и параллельности
    choose-model/      общий выбор модели и параллельности, localStorage
    manage-providers/  API провайдеров и списка моделей
    edit-prompts/      API промптов
    publish-tracker/   публикация результата в Jira
  entities/
    agent/             типы, AGENTS, ROSTER, AgentAvatar и анимации роботов
    run/               типы прогона, обработка событий, результат и связи
  shared/              HTTP API, хеш-маршруты, палитра, утилиты и общие UI-компоненты
```

В `entities/agent/model/agents.ts` массив `AGENTS` содержит 8 базовых ролей,
а `ROSTER` добавляет Архитектора перед Генератором задач — всего 9.
Витрина и сцена главной используют `ROSTER`; состав графа прогона зависит от его данных.

## Где искать ошибку

Пути ниже указаны относительно `frontend/src/`:

- **Демонстрация лендинга:** `features/team-run/model/computeRunFrame.ts` вычисляет состояние
  по времени; тайминги — в `timeline.ts`, сценарий — в `scenario.ts` той же папки.
- **Геометрия сцены и полёты:** `widgets/agent-stage/model/`;
  SVG и эффекты `fx-*` — в `widgets/agent-stage/ui/scene/`.
- **Вид и анимация роботов:** `entities/agent/ui/AgentAvatar.tsx` и `avatar.css` в той же папке.
  Набор ролей — в `entities/agent/model/agents.ts`.
- **Статусы реальных агентов:** `widgets/agent-flow/model/agents.ts`. Для новых записей статус
  «работает» определяется границами вызова модели, а не паузами между токенами.
- **События и повторяющиеся истории:** `features/run-stream/model/useRunStream.ts` и
  `entities/run/model/applyEvent.ts`. При загрузке записи результат из API не должен
  повторно добавлять истории, которые ещё поступают через SSE.
- **Связи с источниками:** `entities/run/model/trace.ts`;
  отображение — в `widgets/trace-map/` и `widgets/inspector/`.
- **Мобильная навигация:** `widgets/console-shell/ui/ConsoleShell.tsx` и `app/styles/console.css`.
  Шапка, шторка агента и жесты графа — `widgets/agent-flow/ui/FlowHeader.tsx`,
  `widgets/agent-flow/ui/AgentFlow.tsx`, `widgets/agent-flow/model/usePanZoom.ts` и `widgets/agent-flow/flow.css`.
- **Выбор модели:** `features/choose-model/model/modelChoice.ts`;
  список провайдеров — `features/manage-providers/`.
- **Цвета:** токены Tailwind — `app/styles/index.css` и `console.css`,
  палитра SVG — `shared/config/palette.ts`.
